# Local Network Integration Test

The repository includes a disposable Docker Compose environment that exercises
the routed access boundary without using Tailscale's hosted control plane. It
starts Headscale, three Tailscale nodes, and a simulated Android endpoint:

- `integration-router` advertises only `10.80.0.2/32`;
- `integration-controller` is placed in the generated nftables source
  allowlist;
- `integration-intruder` is enrolled in the same local tailnet but is not in
  that allowlist; and
- the simulated Android endpoint echoes TCP traffic on port 5555.

The test creates a one-hour reusable Headscale pre-auth key, enrolls all three
nodes against the local Headscale URL, approves the router's `/32` route, loads
the nftables rules generated by `routerctl`, and proves both the positive and
negative paths. Headscale update checks, log upload, and public DERP maps are
disabled. A deliberately unreachable local DERP entry satisfies Headscale's
configuration requirement; peers communicate directly on the private Compose
network.

Run it from the repository root:

~~~shell
just headscale-test
~~~

The current shell must be able to access the Docker daemon. If Docker group
membership was added after login, either start a new login session or run:

~~~shell
sg docker -c 'just headscale-test'
~~~

The test requires Docker Compose, `/dev/net/tun`, and permission to create
containers with `NET_ADMIN` and `NET_RAW`. It pins the Headscale, Tailscale, and
Alpine image versions. Containers, networks, and volumes are removed on exit.
Set `KEEP_HEADSCALE_TEST=1` only while debugging to retain them, and remove the
Compose project afterward.

This test is intentionally not a production deployment recipe. Headscale's
container documentation does not recommend containers for a production
Headscale server, while this environment is short-lived and contains no real
credentials.

## Security coverage and limits

This test covers local control-plane enrollment, subnet-route approval, the
generated typed nftables controller/guest set, reply traffic, and denial of a
second enrolled node. It therefore verifies that tailnet membership alone does
not grant access to the simulated Android endpoint.

It does **not** test Tailnet Lock. Headscale is a compatible coordination
server, not an implementation of Tailscale's Tailnet Lock trust root. Tailnet
Lock signing and revocation require a separate acceptance test against the
dedicated production Tailscale tailnet. The test also does not cover libvirt,
Android boot, ADB authorization, Scrcpy Remote, or GPU acceleration.

See the [Headscale route documentation](https://headscale.net/0.27.0/ref/routes/)
and [container documentation](https://headscale.net/stable/setup/install/container/)
for the upstream commands and deployment caveat.
